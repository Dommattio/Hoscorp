Certificacion de Entrega - Entrega 3: Comunicacion sincrona y asincrona

Modulo 3 - Comunicacion y sincronizacion en sistemas distribuidos

Aca se agrega un canal sincrono y otro asincrono entre componentes del sistema, mas la resolucion demostrable de un caso de concurrencia (por ejemplo, dos escrituras simultaneas sobre el mismo recurso).

Que evalua esta entrega: Que el grupo entienda cuando corresponde cada semantica de comunicacion, no solo que el sistema "funcione".

Checklist de la entrega

Requisito de la entrega Cumple Justificacion breve / evidencia
Hay un canal de comunicacion sincrono funcionando entre componentes (ej. REST/gRPC). X Si   No Implementado mediante HTTP/REST. Opera entre el Frontend y el Backend Clinico (GET /api/records, PUT /api/records/:id) y mediante llamada sincrona directa inter-servicio entre Backend y Notificaciones (GET /api/records/:id/sync-audit-check -> /api/validate-audit).
Hay un canal de comunicacion asincrono funcionando entre componentes (ej. cola de mensajes). X Si   No Implementado mediante RabbitMQ (AMQP :5672) con Topic Exchange hoscorp.events y cola durable hoscorp.notifications.queue. El backend emite eventos (clinical.record.created, clinical.record.updated, clinical.record.conflict) consumidos por el worker en background.
Esta justificado por que se uso cada semantica en cada punto del sistema. X Si   No Sincrono: Para lectura inmediata y confirmacion transaccional critica donde el usuario medico requiere certeza de consistencia.
Asincrono: Para auditoria inmutable, alertas y desacoplamiento temporal de tareas lentas que no deben degradar la atencion medica.
Se identifico un caso de concurrencia concreto (ej. dos escrituras simultaneas sobre el mismo recurso). X Si   No Anomalia de Actualizacion Perdida (Lost Update) en historias clinicas: dos facultativos (o sincronizacion automatica y medico) modifican simultaneamente el diagnostico del mismo paciente sobre la misma version base (rec-1001).
Ese caso de concurrencia esta resuelto y la solucion puede demostrarse (no solo descripta). X Si   No Resuelto con Control de Concurrencia Optimista (OCC) con versionado numerico. La primera escritura avanza a version 2 (200 OK); la segunda colisiona con version obsoleta y es rechazada con HTTP 409 Conflict. Demostrable por script y por UI.

Evidencia adicional

Como reproducir el caso de concurrencia resuelto (pasos o script de prueba):

1. Por consola con script automatizado: Ejecutar en terminal .\scripts\test-concurrencia.ps1 o node .\scripts\test-concurrencia.js. Retorna Hilo 1: 200 OK e Hilo 2: 409 Conflict.
2. Por interfaz web interactiva: Abrir http://localhost:3000 y presionar el boton "Ejecutar 2 Escrituras Simultaneas" en el panel de Concurrencia.
3. Documentacion completa: Consultar docs/informe-tecnico-comunicacion-concurrencia.md y docs/checklist-entrega3.md.
