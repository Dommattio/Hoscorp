Laboratorio de Concurrencia: Dos Escrituras Simultaneas

Resolucion demostrable del problema de actualizacion perdida (Lost Update) mediante Control de Concurrencia Optimista (OCC).

Demostracion Empirica

Dos profesionales intentan modificar simultaneamente la misma historia clinica habiendo leido la misma version base. Con OCC, una transaccion avanza la version a V+1 (HTTP 200 OK), mientras la segunda detecta que su version es obsoleta y es rechazada preventivamente con HTTP 409 Conflict, preservando los datos clinicos.

Guia Rapida para el Docente

Pruebas en Vivo

Ejecuta estos comandos en tu terminal para validar los canales y la concurrencia en tiempo real:

1. Prueba automatizada de concurrencia (OCC): .\scripts\test-concurrencia.ps1 Dispara dos escrituras simultaneas y valida codigos HTTP 200 OK y 409 Conflict.
2. Demostracion integral de los 5 requisitos: .\scripts\demo-completa.ps1 Prueba secuencial de canal sincrono, canal asincrono RabbitMQ y OCC.
3. Probar llamada sincrona inter-servicio: curl http://localhost:5000/api/records/rec-1001/sync-audit-check El backend consulta de forma bloqueante al servicio de notificaciones.
4. Consultar bitacora asincrona en RabbitMQ: curl http://localhost:5001/api/audit-logs Muestra los eventos capturados y procesados por el worker.
5. Panel Web de RabbitMQ: http://localhost:15672 (guest / guest) Muestra las metricas en vivo de exchanges, colas y tasa de mensajes.
