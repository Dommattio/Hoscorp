Entrega 2: Infraestructura
Módulo 2 — Arquitectura de infraestructura
El objetivo de esta entrega es tener un esqueleto real con al menos dos nodos separados (contenedores o procesos), no una maqueta visual. El grupo debe poder mostrar que ambos nodos corren de forma independiente y justificar el modelo de ejecución elegido.
Qué evalúa esta entrega: Que la separación física entre nodos sea real y justificada, no interfaces sin backend.

Requisito de la entrega Cumple Justificación breve / evidencia
Hay al menos dos nodos separados funcionando (contenedores o procesos distintos). [X] Sí
[ ] No		 Dos contenedores Docker independientes: Nodo 1 (Backend API) con Node.js en puerto 5000 y Nodo 2 (Frontend) con Nginx en puerto 3000. Cada uno posee su propio Dockerfile, PID namespace y stack de red.
La separación es real: cada nodo puede iniciarse/detenerse de forma independiente. [X] Sí
[ ] No		 Cada contenedor puede iniciarse o detenerse de forma autónoma (docker compose stop backend). Al detener el backend, el frontend permanece activo con alerta en tiempo real. Al detener el frontend, el backend continúa respondiendo solicitudes REST.
Se identificó el modelo de ejecución elegido (cliente-servidor / P2P / microservicios). [X] Sí
[ ] No		 Modelo Cliente-Servidor Distribuido / Microservicios orientados a dominio, comunicados a través de una red virtual tipo bridge (hoscorp-net) con Reverse Proxy HTTP/REST.
El modelo de ejecución elegido está justificado en función del caso de uso. [X] Sí
[ ] No		 En un sistema de historias clínicas unificadas (Hoscorp), la separación física es mandatoria para resguardar la privacidad y soberanía de los datos de salud, aislando la lógica de persistencia clínica del cliente web de consulta.
El README explica cómo levantar el entorno localmente (paso a paso). [X] Sí
[ ] No		 El archivo README.md detalla paso a paso los requisitos, comandos de despliegue con Docker Compose, verificación de endpoints y scripts interactivos de prueba.
